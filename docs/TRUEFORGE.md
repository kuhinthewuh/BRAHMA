# TrueForge Assessment

TrueForge is an open-source agent harness that manages model calls, tools, sessions, and sandboxed execution. 

## Key Findings

1. **Local TrueForge vs Cloud**
TrueForge can run entirely locally without a TrueFoundry cloud account using the `@truefoundry/trueforge` package.

2. **SDK/API**
The `@truefoundry/trueforge-sdk` package is the main programmatic way to interact with TrueForge's API, manage sessions, and execute tasks.

3. **Sessions and Turns**
TrueForge operates via explicit sessions which manage chat history and state. "Turns" represent the back-and-forth between the system and the agent.

4. **Streamed Events**
The SDK provides ways to stream events (tokens, tool calls, tool results) to provide real-time feedback.

5. **MCP & Subagents**
TrueForge supports the Model Context Protocol (MCP) to supply external tools to agents. It natively supports spawning subagents to distribute tasks.

6. **Daytona Sandbox Execution**
Code generated by the agent can be executed in isolated environments (Daytona) to safely run and verify code prior to deployment.

7. **Human Checkpoints**
TrueForge natively supports human-in-the-loop workflows where the agent pauses and waits for explicit approval before proceeding with critical actions.

## Current Implementation Details

The BRAHMA backend officially uses TrueForge for agent orchestration.

- `BRAHMA_MODE=live`: The **actual TrueForge** runtime is used. This is the **hackathon presentation mode**.
- `BRAHMA_MODE=test`: The **deterministic proxy** is used. This is for **deterministic testing only**.

**Note on Windows Execution:**
A native bug in `@truefoundry/trueforge` v0.1.4 causes an ESM loader crash on Windows due to absolute pathing (`c:\...` instead of `file://`). We have successfully bypassed this bug using a custom Node ESM loader (`loader.mjs`). There is no need for a proxy fallback just for Windows; the live mode is fully supported.
